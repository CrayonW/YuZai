# 鱼仔 PixiJS 分层桌宠改造设计

## 背景

当前项目基于“视频生成 -> 切透明 PNG 序列帧 -> Canvas 播放”的方式实现桌宠动作。这个路线已经能让桌面上看到一只会动的猫，但在互动和流畅度上有明显上限：

- 动作之间容易硬切，靠补过渡帧只能缓解，不能从根上解决。
- 鼠标跟随、拖拽、耳朵反应这类实时互动很难用固定视频自然表达。
- 每新增一个动作都依赖视频生成、去水印、抠像、抽帧、验收，制作链路重。
- 动作数量越多，调度越复杂，但“活着的感觉”提升不稳定。

本次改造目标是从“动作视频驱动”转为“分层角色 + 实时参数驱动”，先让一个坐姿鱼仔真正有连续互动感。

## 已确认决策

- 视觉方向：A2 手绘分层感。
- 角色参考：以用户提供的 `鱼仔参考图.png` 为身份参考。
- 风格取向：外观像鱼仔，互动稍微夸张一点。
- 资产策略：先制定完整美术/分层规范，再产出专业分层稿。
- 交付要求：必须提供 PSD 或等价分层工程源文件，同时导出运行时透明 PNG。
- 运行时底座：PixiJS 场景树。
- 迁移策略：直接替换旧 Canvas 序列帧播放主流程，不做 `sequence | layered` 双模式切换。
- 第一版范围：只做高质量坐姿鱼仔，不追求大量动作和完整走路/睡眠姿态链。

## 目标体验

第一版完成后，桌面上应显示一只像鱼仔的手绘分层猫。它不是播放一段固定视频，而是持续响应环境和鼠标：

- 待机时有轻微呼吸、随机眨眼、尾巴轻摆。
- 鼠标移动时，头部和眼睛连续跟随。
- 鼠标靠近时，耳朵、眼神和尾巴出现明显但不过度的反应。
- 拖拽时身体有拉伸、滞后和回弹，形成明确手感。
- 点击或轻戳时，眼睛、耳朵、头部产生短促可混合反应。

验收重点从“有多少动作”改为“是否连续、是否像活物、是否像鱼仔”。

## 资产包规范

第一版资产目录建议：

```text
assets/layered-pets/yuzai/

    yuzai.psd
  layers/
    body_base.png

    head_base.png

    ear_right.png
    eye_left_iris.png
    eye_right_iris.png

    eye_right_lid_upper.png

    front_leg_right.png
    paw_left.png
    paw_right.png
    tail_01.png
    tail_02.png
    tail_03.png
  rig.json
  identity.json
```

程序只消费 `layers/*.png` 和 `rig.json`。`source/yuzai.psd` 是美术维护源文件，必须保留在资产交付规范中。后续如果 PSD 文件体积过大，可以通过 Git LFS 或外部资产包管理，但规范仍要求存在等价分层源文件。

### 身份锁定

`identity.json` 用于记录鱼仔身份验收标准，避免后续生成或重绘跑偏。第一版需要锁定：

- 灰白英短感。
- 灰色头顶和脸颊。
- 白色鼻梁从额头向鼻口区域延伸。
- 金色圆眼，黑色瞳孔，高光明显。
- 粉色鼻子和短鼻口。
- 白胸、白前腿、灰背。
- 坐姿厚实，整体圆润。
- 深灰尾巴贴近身体。

`identity.json` 不作为第一版运行时核心依赖，但作为资产审核和后续换猫模板的标准文件。

### 绑定数据

`rig.json` 是运行时核心，描述每个 layer：

- `parent`：父级节点。
- `zIndex`：遮挡顺序。
- `texture`：PNG 路径。
- `position`：默认位置。
- `pivot`：旋转/缩放中心。
- `rotationRange`：允许旋转范围。
- `scaleRange`：允许缩放范围。
- `parameters`：受哪些运行时参数影响。

第一版必须支持以下参数：

- `lookX` / `lookY`：头部和眼睛看向鼠标。
- `breath`：身体和胸口轻微起伏。
- `blink`：上眼皮/下眼皮眨眼。
- `earAlert`：耳朵竖起或转向。
- `tailMood`：尾巴摆动频率和幅度。
- `dragSquash`：拖拽时身体拉伸和松手回弹。
- `pawLift`：前爪轻微抬起。

## 运行时架构

Electron 主进程继续保留现有能力：

- 透明、无边框、置顶桌宠窗口。
- 托盘菜单。
- 右键菜单。
- 窗口拖拽。
- 位置、大小、动作频率等本地设置。
- 全局鼠标位置和靠近检测。

Renderer 动画核心替换为 PixiJS 分层渲染：

- `LayeredPetRenderer`：创建 Pixi Application，加载资产包，绘制角色层级。
- `LayeredPetRig`：解析 `rig.json`，建立部件父子关系。
- `PoseParameterController`：维护连续参数值和缓动。
- `MotionMixer`：把待机、鼠标、点击、拖拽等意图混合成最终参数。
- `InteractionIntentAdapter`：把现有行为层事件转换为参数目标。

旧的序列帧主流程不再作为目标架构的一部分。迁移时可以临时参考旧资源和旧测试脚本，但最终主渲染路径应由 Pixi 分层角色承担。

## 第一版 MVP 行为

### 待机生命感

坐姿鱼仔默认保持静态姿势，但叠加低频参数：

- 身体轻微呼吸。
- 胸口和头部有极小幅度跟随。
- 尾巴低频摆动。
- 随机眨眼。
- 偶尔慢眨眼。

### 鼠标注视

鼠标进入关注范围后：

- 眼球跟随鼠标方向，幅度比真实猫稍夸张。
- 头部轻微跟随，幅度保守。
- 鼻口和胡须可跟随头部整体移动。
- 鼠标离开后缓慢回到默认姿势。

### 靠近反应

鼠标进一步靠近时：

- 耳朵轻微竖起或转向。
- 眼睛略微睁大。
- 尾巴摆动节奏变化。
- 反应强度按距离连续变化，而不是播放固定片段。

### 拖拽手感

拖拽窗口或角色时：

- 身体沿拖拽方向轻微拉伸。
- 头部有滞后。
- 尾巴产生惯性摆动。
- 松手后整体回弹到默认姿势。

### 点击/轻戳

点击角色时：

- 快速眨眼或半闭眼。
- 耳朵抖动。
- 头部轻微回避或看向鼠标。
- 不做复杂生气动作，避免第一版资产范围膨胀。

### 睡眠暂缓

第一版不做完整趴下、睡着、醒来的姿态链。可以通过慢眨眼和较低尾巴频率表达轻微困倦，但完整睡眠作为第二阶段姿态资产包处理。

## 非目标

第一版不做：

- 批量生成新动作视频。
- 大量视频切帧接入。
- 完整走路循环。
- 完整睡眠姿态链。
- Spine/Live2D 外部工程接入。
- 新旧渲染模式长期并存。
- 把动作数量作为主要完成指标。

## 测试和验收

第一版验收应覆盖：

- `npm run typecheck` 通过。
- `npm run build` 通过。
- 桌宠窗口能显示 Pixi 分层鱼仔。
- 多帧截图确认不是静态死图。
- 鼠标移动时头眼连续跟随。
- 鼠标靠近时耳朵/眼神/尾巴反应明显。
- 拖拽时有拉伸、滞后、回弹。
- 没有视频切换式硬切。
- 鱼仔身份特征符合 `identity.json`。

如果旧文档型校验仍引用被清理的历史 docs，应优先调整校验入口，使当前运行验证围绕 Pixi 分层资产和桌面运行效果。

## 实施阶段建议

1. 资产规范阶段：定义 `assets/layered-pets/yuzai` 目录、`rig.json`、`identity.json` schema 和示例。
2. 临时验证资产阶段：用简化手绘 PNG 验证 Pixi 分层渲染、层级和参数。
3. 运行时阶段：接入 PixiJS，替换 renderer 主流程，保留 Electron 窗口能力。
4. 交互阶段：实现呼吸、眨眼、头眼跟随、耳朵、尾巴、拖拽回弹。
5. 鱼仔资产阶段：按规范替换为正式鱼仔分层资产。
6. 清理阶段：移除不再需要的序列帧主流程和旧验证入口。
